1.1.0
-----------------------
Dynamic loading of 2D and 3D fluid velocity data, for highly-resolved fluids where RAM is a constraint.
- New FluidData class (per-source subclasses); all loaded fluid data is now a FluidData instance.
- Fluid data handling moved out of Environment into a new fluid module.
- Velocity field components are plain ndarrays; all numpy/scipy/matplotlib operations work on them directly.
- tile_flow is now Environment.tile_domain (implemented on FluidData).
- Domain tiling temporarily raises NotImplementedError; it returns with 2D and 3D support.
- Environment.extend was removed.
- FluidData is documented in the API reference, including the INUM interpolation-in-time tradeoff.
- Plots now show mean agent speed and its spread in place of mean and max fluid speed; plotting no longer loads fluid data for statistics.
- New FluidData.get_mean_velocity returns the spatial mean of each velocity component at any time.
- New Environment.read_openfoam_vtk_data reads OpenFOAM VTK exports (foamToVTK), including dynamic loading.
- OpenFOAM cell-centered data is reordered onto its grid and the boundary patches spliced on to recover the full domain.
- The OpenFOAM reader rebuilds the timeline from the .vtm manifests, then the dump files, then unit steps, warning which source it fell back to.
- The OpenFOAM reader checks the second dump against the mesh read from the first, catching a series whose cell ordering changes.
- New read_openfoam_vtk_data(require_boundary=False) extrapolates the interior out to any domain face no boundary patch covers, rather than failing.
- Where OpenFOAM boundary patches disagree along a domain edge, a no-slip zero now wins instead of being averaged away.
- Fluid loaders warn and carry on when a dump the time series declares is missing, rather than failing.
- plot_all: new playback_rate (simulated seconds per second of video) sets movie speed. Defaults to 1, real time, changing existing movies.
- Plotting after a failed time step shows the recorded history and leaves the incomplete step out.
- New Environment.record streams agent state to a run archive on disk as a run proceeds, instead of holding the whole run in memory.
- Archives survive a hard kill: metadata is written up front, files appear atomically, and the timeline is recovered by scanning what landed.
- New planktos.load_run reads an archive back. Reading one capture touches only the chunk it lives in, so a run larger than memory stays usable.
- New Environment.record(capture_interval=k) keeps state every k-th step, in the archive and in time_history/pos_history/vel_history alike.
- Recording into a non-empty directory writes to a timestamped sibling instead of overwriting it, and warns naming the path used.
- Fluid and mesh loaders now record what produced the data, which an archive stores so a run can say what it was months later.
- New Environment.record(fluid=) stores what a plot needs from the fluid, so replaying a dynamically-loaded run no longer streams the dataset a second time.
- Vorticity is written per fluid dump, in the source's own format beside its own dumps, only when the solver printed none and the field is not held in memory.
- New Environment.record(fluid='quiver', quiver_shape=) stores a downsampled velocity field per dump, for quiver backdrops. Opt-in; vorticity is the default.
- New RunArchive.dump_stats and RunArchive.quiver read the fluid half of an archive back.
- Plots and movies draw the fluid from what Environment.record wrote, so replaying a dynamically-loaded run costs no fluid reads and needs no extra argument.
- Vorticity colour limits and quiver arrow scales now come from a recorded run's own extrema, so two plots of it agree instead of drifting with what has been drawn or loaded.
- New Environment.record(plot_all=) renders a movie when the with block ends, including when the run raised.
- Swarm.move now raises when the Environment holds more than one Swarm; use Environment.move_swarms. It previously warned and froze the others, misaligning their histories.
- Bug fix: adding a Swarm to a different Environment now removes it from its previous one, which kept moving it and left it in both.
- Bug fix: set_canopy_flow works with scalar u_star/U_h/beta, which raised TypeError, and a zero wind parameter now gives zero flow instead of nan.
- Bug fix: set_canopy_flow checks the u_star = U_h*beta relation at every time point; with time-varying parameters it raised instead of checking.
- Bug fix: vorticity is now differenced across the wrap on periodic dimensions. The outermost ring of every plot was previously one-sided and wrong.
- The material derivative and the fluid-speed gradient do the same, so agent behavior in the outermost ring of a periodic domain changes slightly.
- Bug fix: indexing a flow component accepts numpy integers, and resolves negative slice bounds; [-3:] previously returned wrapped, wrong data rather than the last entries.
- Bug fix: a fluid grid one point thick in a dimension now reads as 2D on the remaining axes, with a warning. It gave a zero-thickness domain, or failed on first use.
- Bug fix: 2D COMSOL vtu data now loads. The reader supported it but the constructor assumed three dimensions and raised.
- Bug fix: Swarm.plot at a past time with a moving immersed boundary mesh raised AttributeError.
- Bug fix: plot_all raised KeyError in 2D for a swarm with per-agent colors, which have no shared color entry to fall back on.
- Bug fix: plot_all(fluid='vort') raised over a time-invariant flow, which is every analytic flow (brinkman, channel, canopy).
- other minor bug fixes


1.0.3
-----------------------
Bug fixes.
- Bug fix: vorticity backdrops no longer flash through a movie; colour limits are symmetric about zero and never shrink, and a supplied clip is no longer discarded.
- Bug fix: FTLE is now normalized by the time actually integrated, correcting values where neighboring tracers left the domain early.
- Bug fix: a sliding agent released back into free flight can no longer recurse without limit on a degenerate step.
- Bug fix: plotted agent velocity statistics use recorded velocities instead of differenced positions, which were wrong after any collision or periodic wrap.
- Bug fix: Environment.reset clears velocity and props history alongside position history, which it left behind and misaligned.
- A time step that fails or is interrupted partway through now marks the Environment (time=None) and reports the state; move() refuses until it is restored.
- A Swarm subclass that replaces move() instead of apply_agent_model now warns at class definition.
- Plot statistics at the initial time now show the agents' starting fluid drift instead of zero.

1.0.2
-----------------------
Bug fixes.
- Bug fix: calculate_FTLE(swrm=...) raised AttributeError on the first step, and appended to the caller's Swarm history.
- Bug fix: meshes imported by the 'adjacent' method or as a moving mesh now follow the fluid's coordinate shift, as the other methods already did.

- Bug fix: sliding along a moving mesh element no longer depends on the orientation of the coordinate axes.
- Test suite reorganized and deduplicated; immersed-boundary collision coverage now 99%. No library behavior changed.

1.0.0
-----------------------
Moving immersed boundaries are now supported in 2D!
- IB2d import of dynamic boundary meshes
- all 2D plotting routines updated to handle moving immersed boundaries
- both sticky and frictionless immersed boundary interactions included!
- reworked apply_internal_static_BC for 2D and 3D cases, important bug fixes
- swarm.ib_collision is now ib_collision_idx. It is -1 if the corresponding agent did not encounter a mesh element during the previous timestep,
and otherwise gives the index of the first mesh element encountered.
- Swarm and Environment classes are now capitalized.
- Cleans up Swarm and Environment by kicking static methods and loaders to external module. Adds leading underscores to make API cleaner.
- Changes the name of get_positions to apply_agent_model, removes params argument.
- Updated installation instructions and added workflow.
- Optional parallelization of immersed-boundary collision detection: attach any worker pool exposing .map (multiprocessing.Pool, ProcessPoolExecutor, or ThreadPoolExecutor) to a Swarm via the new pool attribute/kwarg. Defaults to serial (pool=None), behavior unchanged.
- get_2D_vorticity vectorized via np.gradient: identical to the old loop on uniform grids, more accurate on non-uniform grids.
- New single-file tutorial for sticky moving boundaries.
- Bug fixes: corrected ib_collision_idx for some collisions; fixed flow_points axis ordering for non-square grids passed directly to Environment(); repaired pytest collection and updated stale intersection/vorticity tests.
- Bug fix: sticky moving-boundary collisions no longer return NaN for perfectly axis-aligned (vertical/horizontal) mesh elements
- Bug fix: motion.highRe_massive_drift now works in 2D. The drag term now broadcasts over the environment's dimension (output unchanged in 3D).
- Bug fix (3D immersed boundaries): agents sliding on a triangle mesh no longer stick at shared triangle edges; this affected coplanar tiled (flat) surfaces and concave folds. 
- Backward-time FTLE is now correct and works; tracer particles only.

Geometry module added to collect workhorse mathematical functions. Explanation of the mathematics and implementation has been added and cleaned up.

Better code organization, including consolidation of IB2d mesh loading

Critical bug fixes in agent-mesh interaction; extensive testing.

Test suite overhaul. The automated tests were reorganized into focused, fast,
deterministic modules under tests/ (geometry, static/moving collisions, flow
generation, temporal interpolation, agent models, swarm lifecycle, analysis, and
I/O loaders). The default `pytest` run is ~1s; the slower full-simulation
parallelization checks are gated behind `--runslow`. Exploratory/visual scripts
moved to tests/manual/ (not collected). Tiny committed fixtures in
tests/fixtures/ (regenerable via tests/fixtures/_gen_fixtures.py) give the first
automated coverage of the moving immersed-boundary import. The new tests
uncovered four latent bugs; all four are now fixed with regression tests (the
sticky moving-boundary NaN, the closest_dist zero-length crash, the
save_fluid/save_2D_vorticity pyvista breakage, and backward-time FTLE, all listed
above), so the suite has no remaining xfails. A few non-blocking follow-ups remain,
e.g. full moving-immersed-boundary support in FTLE.


0.7.0
-----------------------
Coloring for individual agents
Agents can now be individually colored by setting a property. They can also be named. This is documented in the Swarm constructor.

Plotting of agent headings
The direction individual agents are facing/moving can now be plotted in 2D. This is turned on by default. The heading is drawn from the agent's current velocity unless individual heading angles are a specified as an agent property.

Property history
Agent property history can now be optionally saved. This is necessary for plotting agents that change color over time (e.g., highlighting certain agents that fulfill a given condition) and other situations.

New method after_move
This method is called after agents finish moving. It can used to act on their final positions and velocities which was formerly not possible because interactions with immersed boundaries would come after the user defined behavior.

Euler_brownian_motion is now robust to arbitrary starting positions/velocities, not just the current state of all agents together.

define_pic_grid
This new method of the Environment class implements a particle-in-cell method for agents interacting with neighbors. It can be utilized to make user-defined behavior more efficient.

ex_poisson_search.py
New example demonstrating how to handle arbitrary switching times in Planktos and demonstrating a basic intermittent search strategy.

Bug fixes.
